# 개발 로드맵

## v1.0 목표

실제 Google Play 출시가 가능한 최소 제품을 완성한다.

---

## Phase 1 — 급여 계산 엔진

- 순수 Kotlin 도메인 모델
- 기본급 계산
- 자정 통과 처리
- 야간구간 계산
- 휴게구간 제외
- 연장/야간 등 가산항목 구조
- 단위 테스트

완료 기준: Android UI 없이 JVM 테스트만으로 계산 결과 검증 가능.

---

## Phase 2 — 로컬 데이터 계층

- Room 도입
- WorkProfile / Shift / Break 저장
- Repository
- 진행 중 Shift 복구
- 설정 변경 시 과거 조건 Snapshot 보존

---

## Phase 3 — 기본 설정

- 시급 설정
- 사업장 조건 설정
- 선택 근무조건 입력
- DataStore 또는 적절한 저장 계층 적용

---

## Phase 4 — 핵심 근무 흐름

- 출근
- 실시간 예상 급여
- 경과시간
- 휴게 시작/종료
- 퇴근
- 정산 결과
- 근무 저장

이 단계에서 제품의 핵심가치가 동작해야 한다.

---

## Phase 5 — 근무 기록

Issue #5에서 월간 목록·유급/휴게시간·예상 급여 합계, 상세, 시간/시급/휴게 수정,
수동 완료 근무 추가와 확인 후 삭제를 구현했다. [정책과 검증](WORK_HISTORY.md).

- 월간 기록
- 월 총 근무시간
- 월 예상 수입
- 개별 근무 상세
- 과거 기록 추가/수정
- 완료 기록 삭제 (확인 후 휴게와 함께 삭제)

---

## Phase 6 — 백그라운드/지속 알림

Issue #6에서 optional specialUse 서비스, 20초 예상 급여 알림, 휴게·재개·퇴근 액션과
Room 상태 동기화를 구현했다. 권한 거부·서비스 중단에도 기록과 앱 복구를 보존한다.
재부팅 자동 시작은 하지 않는다. Play specialUse 승인은 별도 심사 대상이다.
[정책과 검증](SHIFT_NOTIFICATION.md).

- Foreground Service 기술 검증
- 지속 알림
- 현재 근무 상태 표시
- 알림에서 휴게/퇴근
- 앱 프로세스 종료/재실행 복구
- 기기 재부팅 등 예외 상황 검토

---

## Phase 7 — 품질

- 계산 경계값 테스트
- 앱 상태 복구 테스트
- UI 오류/빈 상태
- 잘못된 시간 입력 방어
- 접근성 및 다크모드 점검

## Phase 8 — 출시 준비

- 앱 이름/아이콘 확정

- Release build

## v1.0 완료 조건

- 출근/휴게/퇴근 가능
- 앱 화면에서 실시간 예상 급여 증가
- 기본 급여 및 지원 가산항목 계산
- 근무 Breakdown
- 과거 기록 저장/수정
- 월간 예상 수입
- 진행 중 근무 복구
- 계산 엔진 자동 테스트
- 지속 알림 기술 검증
- 광고 정상 노출
- 출시 필수 문서 준비
- 테스트 트랙에서 치명적 크래시 없음

## 2026-10-10 운영 상태

> 2026-10-10부터 캡스톤 RC 완료 시까지 2주 앱 출시 트랙 일시 중단. 14일 출시 목표의 시계도 중단하고 재개 시 목표일을 다시 정한다. Phase 1~6 구현 상태를 보존하며 Phase 7 품질, Phase 8 AdMob/Play 출시 준비는 미완료로 유지한다.
